## 2. 系统概览

- **Product 轨**：RetailGraph（只读、只能提议）→ OperationWorkflow（HMAC grant、一次性 nonce、申请/审批分离、first-decision-wins、幂等重试）→ QueryEngine（AST 白名单 + EXPLAIN 阈值 + 对账）→ `ops_read` 屏障视图；提案/执行/审计全链留痕，身份列裸投影在策略层被拒。
- **BIRD 轨**：EvaluationRunner（任务级恢复、同题双模式串行守卫）→ 官方 ADK 编排器子进程（stdout/stderr 落盘）→ 三容器拓扑（system-agent / user-simulator / db-env）；agent 零 GT 可见性（9 条契约断言 + 运行时拒绝检查）。
- **模型网关**：能力/价格快照驱动（供应商更名 2026-09-10 实测零代码切换）、canonical JSON 请求绑定、逐轮费用估算、协议诊断插桩、fail-closed。
- **遥测**：agent spool JSONL（逐轮 token/费用/band）→ fail-closed 导入 eval 库；UI 评测中心读真实数据。

## 3. 评测结果与结论

### 3.1 BIRD A4 Full（600 题目标）

- **c 批 300/300 任务完成**（12×25 子批 + 4 集余额失败重试 sweep + 1 infra 重试 = 305 attempts，300 succeeded / 4 failed / 1 infra；agent $3.46 = $0.0113/成功任务）；**a 批 223/300**（225 attempts，$6.15 = $0.0273/attempt；75 集经预算裁定截停，2 集确定性 `ContextBudgetExceeded`——a 模式长对话强制上下文超 64K prompt 预算，修复需动冻结的输出水位线，裁定不修）。
- **有效评分 523 条 reward>0 = 0**（A4；2 个 a 失败集无评分）；含消融 120 条有效评分后仍 0 正值。能力门未达。
- **机制（决定性发现）**：官方 c 模式相位记录不携带任务问题 + 我方 adapter 上下文重建缺陷 → 逐轮失忆（Day 6 定位并修复）；修复后失败收敛于**领域知识缺口**——知识查询 miss/定义不全 → agent 自造公式 → user-simulator 拒答 → Phase 1 失败。a 模式诊断同源（探索 SQL 全对、公式靠猜）。

### 3.2 消融 §17.2（执行反馈修复）

30 配对题 × c/a × A/B = **120/120 succeeded**。A（首次失败停止）vs B（官方有限修复）：**P1 完全相同（0/60 vs 0/60）——修复救回 0 集**；B 多耗费用 ~2.4–2.7×、轮次 ~1.37×。结论：当前能力水平下修复价值为零（本样本描述性结论，§17.2 明文不做普遍化），修复的无效性限于该失败层。

### 3.3 产品评测 §17.1（小 Schema 是否需要检索）

题集从零构建（50 题中文问题 + 参考 SQL，双验证 = 真实库执行 + AST 策略合规；zh glossary 术语桥）。A/B×40 + 封闭 10（胜者配置）：

| 条件 | 正确 | 可执行 | Recall@5 | tokens |
|---|---|---|---|---|
| A 全量 Schema | 3/40 | 7/40 | 1.000 | 170,696 |
| B BM25 检索（top-5、相对分 ≥0.3） | 2/40 | 4/40 | 0.910 | 64,046（−62.5%） |

**预注册判据否决检索路线，全量 Schema 胜出**——与 §10.2 预期一致（小 Schema 下全量更有效），检索省 62.5% token 但丢表覆盖。构建期发现并修复产品真缺陷：查询策略函数白名单误杀布尔运算符（AND/OR 查询全部不可执行）。

### 3.4 诚实边界

- reward=0 是评测的真实结果；所有「成功」结论限于工程与流程维度（succeeded 率、机制定位、成本控制）。
- 产品评测为**单步 SQL 生成配置**（无 SqlReasoner 修复环、无多步调查）；策略合规缺口 ~60% 是该配置的如实测量，非产品全链路能力。
- a 批截停、2 集不修、题集由同一系统构建——全部为明示裁定并留痕，非隐藏失败。

## 4. 过程决策（预算与纪律）

- **预算**：160 元线，实际 ≈88 元（55%）。Pilot 预算终裁 FAIL（外推 457.6 元）触发策略修复 → 总账压回预算内，是本项目最重要的过程转折。
- **off-peak 纪律**：peak 档单价 2×；全部付费调用零 peak 泄漏；批次估算贴线时宁可分窗。
- **安全暂停**：余额耗尽（c 批 b04）、同因两现（a 批 b09 后 GC7 停）、越线风险（午窗截止）——三次全部立即停 + 呈用户裁定。
- **裁定量化**：a 批照跑（~53 元）→ v4 先行验证（$0.056，reward 中性回退）→ 并发 2→4（2.3× 提速，试点验证）→ GC7 停 → 截停（省 14.5 元）。每步有数据、有预声明判据。

## 7. Codex 审查与更正（2026-09-18）

Codex 只读审查（`docs/reviews/codex-review-findings.md`，23 条声明抽验 + 11 项代码 findings）发现的问题与处置：

1. **成功数重复计算（已更正）**：c 批「304/304」把 sweep 重试重复计入（DB 实况 = 305 attempts：300 succeeded / 4 failed / 1 infra，300 个任务各有成功 attempt）；A4「527/529、0/627」口径不可重建 → 更正为 530 attempts / 523 有效评分 / 0 正 reward。
2. **评分假阴性（已修复 + 免费重评分）**：gold（psycopg Decimal）与 agent（QueryEngine str）数值表示边界 + 逐行单元格乱配缺陷 → 4 个真匹配被判错；评分契约重写（参考侧类型锚定 + 一致列置换 + 有序/无序分约），对保存 SQL 免费重评分：A 3→5（12.5%）、B 2→4（10.0%）、封闭 1/10 不变；裁决不变。
3. **代码缺陷（已修复 + 回归测试）**：Runner 停止后排队任务仍会启动（F4）、SIGINT 取消不杀官方子进程（F5）、gather 吞掉状态冲突致 CLI exit 0（F6）、SSE 以 attempt sequence 推进 run cursor 致尾部事件重发（F3）、导入器唯一候选跳过时间窗（F9）、harness 前缀检查窄于 AST 策略（F10）、查询策略身份列包装绕过（F7）与窗口/标量子查询绕过明细 LIMIT（F11）。
4. **口径与措辞（已更正）**：「上下文 token −62.5%」更正为总 token（输入 token 为 −72.9%）；轮次倍率 1.37× 与费用倍率 2.4–2.7× 分列；「88 元」定性为**混合口径估算**（历史平台读数 7.40 + 现存遥测×7.07 + v2 失败轮 $0.0120 补记），非平台实扣终账；「全部付费调用零 peak 泄漏」收窄为「BIRD 轨现存遥测内零 peak 泄漏」；v2 失败轮实际产生 $0.0120 模型费用并计入。
5. **结论收窄**：能力门未达下的 A4 完成为「经裁定在能力门未过下完成有限范围评测」；「全量 Schema 更有效」限定本次预注册实验；「修复不可达层」限定本样本；a 批含 3 集 v4check（混合策略）已脚注。
