# 面试叙事材料（CommerceAnalyst）

> 用途：面试/复盘讲述的项目叙事主线、深挖问题与答案要点。全部数字可在 `docs/reports/` 与账本中回溯。

## 1. 一句话项目

「在 160 元预算内，用 24 天把一个『电商经营分析 + 受控运营』双轨 Agent 从规格推进到 600 题基准评测收官——评测诚实（能力门未达且机制定位清楚）、预算超预期节约（88/160）、过程中发现并修复了三个真实产品缺陷。」

## 2. 叙事主线（90 秒版）

1. **架构**：双轨隔离——受控运营闭环（Agent 只能提议，独立审批后才执行，全程审计）+ BIRD 基准评测轨（agent 对 GT 零可见性，9 条契约断言锁死）。
2. **评测**：600 题基准跑 530 attempts / 523 成功（2 集确定性上下文溢出、75 集预算裁定截停）——有效评分 reward 全零，能力门未达。
3. **机制定位**：不是玄学——知识缺口（目录没有的指标 agent 自造公式、simulator 拒答）+ SQL 质量；消融实证「修复环救回 0 集」；产品轨 A/B 实证「小 Schema 下全量 Schema 优于检索」。
4. **纪律**：peak 单价 2× 全程零泄漏；每 25 集重估；三次安全暂停；88/160 元收官。

## 3. 深挖问题与答案要点

**Q1「reward 全零，这项目算成功吗？」**
答：评测的产出是信息，不是分数。能力门未达但机制定位到可操作层（知识缺口 → 自造公式 → sim 拒答），且改进杠杆做了对照实验：v4 提示策略让行为改善但 reward 中性（$0.056 验证），修复环消融证明救回 0 集。把「为什么是零」钉死，比一个不可解释的正分更有工程价值。所有失败模式 1:1 留痕可复现。

**Q2「讲一个最难定位的 bug。」**
答：c 模式逐轮失忆。表面是 agent 提交 `SELECT 1` 占位符；深挖 spool 遥测发现每轮新会话、上下文只有相位记录；再对官方源码静态核验发现官方语义是「一次 run_session 承载整个澄清循环」——是我方 adapter 每轮只喂最后一条 sim 回复。修复后又遇相位边界（失败反馈开新 Phase）再修。教训：**修复要覆盖状态机的全部入口，不只主路径**（clarify 轮 / 失败反馈轮 / 新 Phase 枚举着写 RED 测试）。

**Q3「讲一个最有价值的发现。」**
答：推理输出水位线。连续两次 `provider_response_invalid` 都在网关边界，只留 sanitized 日志无法定性——插桩后一发命中：reasoning 吃满 8192 输出预算 → finish=length + 空 content → 校验炸成协议错误。对照官方文档确认官方思考默认输出 64K，低于它的任何上限都让偶发 blowout 致命。修到 64K 后端到端立即健康。附带产出：策略函数白名单误杀布尔运算符（AND/OR 查询全不可执行）是后来建评测时发现的——**「离线全绿」不等于产品可用**的又一实证。

**Q4「预算怎么控制的？」**
答：三件套——①单价分档（peak 2×）→ 付费一律空闲档，全程零 peak 泄漏；②每 25 集重估 + 预声明判据（越线/同因两现即停）；③把裁定交给数据：a 批跑前锚定 $0.025/集，b01 实测 $0.0274，75 集截停省 14.5 元是算出来的不是拍脑袋。最终 88/160。

**Q5「并发提速怎么做的？」**
答：并发上限冻结在 2（Day 1 spike 契约）。升 4 前先 grep 约束面——CLI 直接被 pydantic 拒绝；改一行 cap + 钉测试 + 单批试点（零 infra、2.3× 提速）再放量。同题双模式碰撞（官方 task DB 命名不含 mode）用清单拆分串行规避。

**Q6「消融实验说明了什么？」**
答：120 集、两个条件只差「失败后允不允许修复」。结果：P1 通过率完全相同，修复多花 2.4–2.7×。说明失败原因在修复不可达层（知识缺口），不是执行细节——这把改进方向从「加修复轮」推向「补知识/提示策略」。

**Q7「产品轨检索为什么输了还值得写？」**
答：§10.2 是可证伪阶梯——预注册判据（正确率 +5pp 或 recall 不降且 token −20%），输了就如实报告「小 Schema 下全量更有效」。检索省 62.5% token、recall 0.91——在小语料上省的这点 token 不值得丢覆盖。价值在方法论：判据先冻结，结果不理想也不改判据。

**Q8「安全/隔离怎么保证的？」**
答：分层——GT 对 agent 零可见（数据不进容器 + 运行时拒绝检查 + 契约断言）；身份列裸投影在 SQL 策略层拒绝；ops_read 屏障视图 + 最小授权；每张写路径有幂等键与审计事件；秘密零入库（allowlist 扫描双遍）。

## 5. 如果重来（复盘）

1. **先冻结评测器再写 Agent**：reward=0 的三周里，一半时间在分辨「是 Agent 差还是评测歧义」——题面/评分的确定性 validator 应该最先建。
2. **知识目录要有运营词汇的中文映射**：知识缺口的主因之一是目录没有中文业务词 → 字段/指标的桥（glossary 是评测时才补的）。
3. **策略面（函数白名单）要写进生成提示**：模型不知道边界就会撞边界；修复环是产品已有的，评测 harness 第一版就该带上。
4. **spool 遥测从 Day 1 就上**：这次的机制定位全靠逐轮 token/费用/序列留痕——可观测性是付费评测的前提，不是附属品。
